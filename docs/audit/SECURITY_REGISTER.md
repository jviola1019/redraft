# 92-item defensive applicability register — 2026-11-20

This expands the static applicability matrix in `SECURITY.md`. Each row names an asset, a conditional prerequisite, observed defense/evidence, verification method/status, provisional severity, acceptance criterion and residual risk. It contains no offensive procedures. Scope is repository inspection plus the explicitly named ordinary contract/integration tests; it is not a production penetration test or a claim of universal safety.

**Severity is provisional impact if the prerequisite and control failure occur**, not a confirmed vulnerability rating, exploit likelihood, CVSS score or release verdict. Critical means possible trust-boundary compromise, High means material confidentiality/integrity/availability impact, Medium means more bounded privacy/availability/integrity impact. An absent local surface is marked unrated rather than scored as a discovered issue.

Verification labels: **No local surface** = corresponding feature not found in the reviewed game route, with no exhaustive platform absence claim; **External operator** = provider/hosting evidence required and not verified; **Inspected** = implementation reviewed without a dedicated executed test for that exact item; **Tested** = normal automated case supports the stated bounded property, with platform behavior still unverified. Evidence references below point to files, not guarantees.

Source evidence: `app/api/game/route.ts`, `app/chatgpt-auth.ts`, `lib/request-body.ts`, `lib/scouting.ts`, `lib/server-data.ts`, `db/schema.ts`, `pnpm-workspace.yaml`, `.github/workflows/ci.yml`. Executed unit/adapter evidence is recorded in `DAILY_BOUNDARY.md` and `DEPENDENCY_PATCH.md`. Daily patch validation: 86 unit tests and 14 quick API cases/259 requests; dependency patch validation: frozen install, TypeScript, build and fresh registry audit. Test scope is not extrapolated to DNS/TLS/provider/production D1.
